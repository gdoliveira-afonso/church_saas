O que é o CRM Celular?

Plataforma SaaS multi-tenant para gestão completa de igrejas e ministérios.

groups Propósito

Centralizar a gestão pastoral de membros, células, escola bíblica e finanças em um único sistema web multi-organização, com controle de acesso por papel e módulos opcionais ativáveis por plano.

layers Stack Técnica
  • Frontend: Vite 7 + Vanilla JS + Tailwind 4
  • Backend: Express.js 5 + Prisma 5 ORM
  • DB: SQLite (dev) / PostgreSQL (prod)
  • Deploy: Docker + Nginx reverse proxy
  • Auth: JWT + Bcrypt + RBAC
  • Extras: Puppeteer (PDF), SheetJS (Excel), PWA
architecture Arquitetura
  • SPA: Hash-based router customizado
  • API: REST + JWT Bearer tokens
  • Multi-tenant: organizationId em todos os models
  • State: Store global (store.js)
  • Segurança: Helmet, rate limiting, CORS, IDOR guards
  • Integrações: API Keys (hashed) + Webhooks

storage 7 Modelos de Dados

1

FinancialAccount

Contas bancárias. Saldo calculado via transações. Extrato com running balance.

2

Fund

Fundos customizáveis (ex: Missões, Obras). Toggle ativo/inativo. Saldo por fundo.

3

ChartOfAccount

Plano de contas hierárquico (pai/filho). 15 categorias pré-carregadas no seed.

4

FinancialTransaction

Ledger central. Tipos: CREDIT/DEBIT. Imutável se gerada por BILL ou DONATION. Paginado.

5

Donation + DonationBatch

Dízimos e ofertas. Suporte a lotes (batch). Cria Transaction atomicamente. Vinculável a Person.

6/7

Bill + BillPayment

Contas a pagar. Status PENDENTE/PAGO/VENCIDO (calculado em JS). Pagamento cria Transaction+BillPayment atômico.

Configurações & Limites por Plano

O que o SUPERADMIN controla na plataforma multi-tenant.

manage_accounts Controles do SUPERADMIN

  • Criar / editar / deletar organizações
  • Definir plano de cada organização
  • Toggle ebdEnabled por organização
  • Toggle financialEnabled por organização
  • Visualizar logs de auditoria globais
  • Backup de dados (sem senhas no response)
  • Deletar todos os dados EBD de uma org
  • Configurações globais da plataforma

tune Configurações por Organização (ADMIN)

  • Nome, logo e branding da congregação
  • Campos customizados de células (cell fields)
  • Gestão de usuários e seus papéis
  • Atribuição de secondaryRoles (EBD, financeiro)
  • Criação de API Keys (hashed) para integrações
  • Configuração de Webhooks externos
  • Logs de atividade da organização

security Camadas de Segurança

Autenticação

JWT Bearer + tokenVersion (invalidação forçada) + Bcrypt (senhas)

Autorização

RBAC com guards por rota + organizationId em todas as queries (multi-tenant isolation)

Infraestrutura

Helmet headers, CORS restrito, rate limiting, IDOR guards, payload 10MB máximo

Auditoria

ActivityLog em todas as ações, logs protegidos por ADMIN/SUPERVISOR/SUPERADMIN
